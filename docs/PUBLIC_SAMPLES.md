## Every disagreement, explained

A disagreement is explained only by evidence the corpus itself contains; anything else is listed in
full under *not explained*.

| Cause | Fields | Evidence | Example |
|---|---:|---|---|
| Elastic's packages read this message in opposite directions | 312 | Elastic's cisco_asa package agrees with TRACELOG on all 118 fields of message 302015 outbound; its cisco_ftd package reverses all 104; Elastic's cisco_asa package agrees with TRACELOG on all 229 fields of message 302013 outbound; its cisco_ftd package reverses all 208 | cisco_ftd src_ip: TRACELOG `172.31.98.44`, Elastic `192.168.205.104` — `Oct 10 2018 12:34:56 localhost CiscoASA[999]: %ASA-6-302013: Built outbound TCP connection 11757 for outside:192.168.205` |
| Direction taken from the connection's own Built message | 396 | on 196 of these fields, Elastic's own event for the same connection's Built message names TRACELOG's source; on 196, that Built event is itself one of the reversed ones in the row above; 4 have no Elastic event for the Built message | cisco_asa src_ip: TRACELOG `172.31.98.44`, Elastic `192.168.80.32` — `Oct 10 2018 12:34:56 localhost CiscoASA[999]: %ASA-6-302016: Teardown UDP connection 11758 for outside:192.168.80.32/53 ` |

Cisco ASA and FTD write the outside end of a connection first in both the Built and the Teardown
message, and only the Built message says which end opened it. TRACELOG reads a Teardown's direction
from its own Built message (matched by device, connection id and both ends); Elastic's pipeline
reads the Teardown in written order, which makes an outbound DNS lookup's teardown come *from* port
53. 281 Teardown fields whose Built message is not in the sample are left empty
rather than guessed.
